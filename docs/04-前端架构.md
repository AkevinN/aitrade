# AITrade 前端架构

> 本文档描述前端应用的页面结构、组件设计、状态管理和数据流。

---

## 一、技术架构

```
React 19 + TypeScript 5.9 + Vite 7
├── UI 组件: Ant Design 5
├── 数据请求: Axios + TanStack Query 5
├── 状态管理: Zustand 5
├── 路由: React Router 7
├── 图表: Recharts 3 + TradingView lightweight-charts 5
└── 主题: Ant Design 暗色主题 (自定义 token)
```

## 四、页面功能详述

### 4.1 Dashboard — 工作台

**文件**: `pages/Dashboard/index.tsx` (~10K)

**功能模块**:
- 🔌 系统连通性检查 (后端 API / Tushare Token / PyTorch)
- 📊 数据准备度统计 (已下载合约数、数据集数、模型数)
- 📋 运行中任务列表
- 🚀 快捷操作入口

### 4.2 DataPrepare — 数据准备

**文件**: `pages/DataPrepare/index.tsx` (~33K, 含子组件)

**功能模块**:
- **数据下载**: 选择合约 + 日期范围 + 周期，从 Tushare 下载
- **CSV 导入**: 上传 CSV → 字段映射预览 → 确认导入 (支持 Bar + Tick)
- **周期聚合**: 从原始 1m 数据聚合为 5m/15m/30m 等派生周期
- **数据预览**: 分页查看已有 K 线数据

### 4.3 ModelTrain — Alpha 模型训练

**文件**: `pages/ModelTrain/index.tsx` (~19K)

**功能模块**:
- **数据集创建**: 选择合约 + 时间段 + 特征库 (Alpha101/158)
- **模型训练**: 选择数据集 + 模型类型 (LGB/MLP/Lasso) + 参数配置
- **训练监控**: 实时进度 + 任务状态
- **模型列表**: 查看/删除已训练模型

### 4.4 CNNTrain — CNN 训练

**文件**: `pages/CNNTrain/index.tsx` (~22K)

**功能模块**:
- **观测组配置**: 添加/编辑语义分组 (目标/大盘/板块/龙头/自定义)
- **输入配置**: 选择数据类型 (Bar/Tick) + 输入周期
- **标签配置**: 选择标签模式 + horizon 参数
- **训练参数**: epochs / batch_size / learning_rate / lookback / dropout
- **模型管理**: 列表 + 详情 + 删除

### 4.5 Signal — 信号分析

**文件**: `pages/Signal/index.tsx` (~10.5K)

**功能模块**:
- **信号生成**: 选择模型 + 合约 + 时间范围
- **信号预览**: 表格展示预测信号值
- **信号列表**: 查看/删除已生成信号

### 4.6 Backtest — 策略回测

**文件**: `pages/Backtest/index.tsx` (~10K) + 子组件 `BacktestCharts.tsx`

**功能模块**:
- **回测配置**: 选择信号 + 资金 + 时间范围 + 基准
- **结果展示**: Sharpe 比率、最大回撤、收益率等统计指标
- **任务监控**: 进度跟踪
- **图表可视化** (图表可视化特性): 在既有 `<BacktestResults>` 统计卡片之后展示净值/回撤曲线与标注买卖点的 K 线，CNN 回测与 Alpha 回测两条路径共用，详见下方 BacktestCharts。

#### BacktestCharts — 回测结果图表容器

**文件**: `pages/Backtest/BacktestCharts.tsx`

> 承载回测专有逻辑（取哪个标的、什么区间、买卖语义映射）的业务容器，把通用图表组件（`components/charts/`）与纯函数适配器（`chartAdapters`）组装起来，消费 `task.result` 的 `trades` / `equity_curve` 字段。

- **净值曲线**: `toEquityPoints(result.equity_curve)` → `<EquityCurveChart>`；无净值数据展示空状态。
- **确定 K 线标的**: 优先 `result.target_symbol`（CNN 回测有），否则取 `trades[0].vt_symbol`（Alpha 回测）。
- **拉 OHLC**: `useQuery` 调 `alphaService.getBarDataDetail(interval, vtSymbol, ...)` 取回测区间行情 → `toOHLCBars`；加载态/错误态由 query 状态驱动，**K 线行情失败不影响净值曲线与统计卡片展示**。
- **买卖点**: `toTradeMarkers(result.trades, barTimeRange)` → `<KLineChart markers=...>`，越界 marker 被过滤。
- **接线**: 接入 `CNNBacktest.tsx`（`interval` 取模型 `input_interval`）与 `AlphaBacktest.tsx`（`interval` 取 `scheme.interval`），置于 `<BacktestResults>` 之后，不改其既有展示。

### 4.7 Resource — 资源管理

**文件**: `pages/Resource/index.tsx` (~12K)

**功能模块**:
- **资源总览**: Tab 切换查看原始 Bar / 原始 Tick / 派生 Bar
- **资源详情**: 点击查看数据预览 (支持分页加载)
- **资源删除**: 单个删除

### 4.8 TradingConsole — 交易操作台

**文件**: `pages/TradingConsole/index.tsx` + 子组件 `ConfigForm` / `ProgressCard` / `DecisionResultCard` / `RiskDetailPanel` / `HistoryTable` / `DecisionTracePanel`

> 把既有实盘原语（`predict_cnn_signals` → `SignalService` → `RiskManager` → `Notifier` → `DecisionStore`，见 docs/08 迭代 6）经 `/api/live/*` 暴露的 UI 层。**仅产出决策与提醒，不自动下单**（no broker submission，见 Requirement 7.4）。

**功能模块**:
- **ConfigForm 配置表单**: 模型（拉 `/api/cnn/models`）、目标标的、方案、决策日期（默认当天）、数据源（`upload`/`pull`）、组合快照（总资金/当前持仓/持仓市值）；提交经 `useMutation` 调 `liveApi.startDecision` 拿 `task_id`；始终提供「触发/重新触发」按钮（Req 6.6）。
- **ProgressCard 进度联动**: 复用既有 `useWebSocket` + `taskStore`，订阅该 `task_id` 进度刷新；任务 `FAILED` 展示错误消息（Req 6.7）。
- **DecisionResultCard 决策结果卡片**: 读 `task.result.decision` 展示 action/手数/价位/信号概率/reason；**始终显示「仅提醒，不自动下单」提示**（Req 7.4）。
- **RiskDetailPanel 风控明细面板**: 展示 `task.result.risk_detail` 逐项 `check`/`passed`/`detail`（Req 6.4）。
- **HistoryTable 历史决策表**: `useQuery` 拉 `/api/live/decisions`，点击行调 `getDecision` 展示详情（Req 6.5）。
- **DecisionTracePanel 决策过程面板**: 展示一次决策的完整 Decision_Trace（决策过程可观测性，Req 8.6），见下方专述。

#### DecisionTracePanel — 决策过程面板

**文件**: `pages/TradingConsole/DecisionTracePanel.tsx`

> 接入 `DecisionResultCard`（结果卡片）与历史决策详情，按**六段 Trace_Section** 分组展示决策过程档案，用于事后回溯与排障（Requirement 8.6）。

- **六段可折叠分组**: 用 Ant Design `Collapse` 渲染六个分组——**运行头 / 推理段 / 取价段 / 决策逻辑段 / 风控段 / 结果段**，默认**全部折叠**。
- **懒加载**: 仅当 `signalId` 存在且**展开任意分组**时才调 `liveApi.getDecisionTrace(signalId)`（`useQuery`，`enabled` 由展开状态驱动）；未展开不发起 `/trace` 请求。
- **404 处理**: 后端返回 404（无过程档案）时分组内显示「暂无过程档案」；其它错误显示通用加载失败提示。
- **风控段复用**: 直接复用 `RiskDetailPanel` 渲染风控逐项 `{check, passed, detail}`，并附「权威结论（`RiskManager.check_buy`）：放行/拦截」。
- **结果段可观测标记**: 展示 `idempotent_hit`（幂等命中）/ `trace_persisted`（过程档案是否持久化成功）/ `abort_reason`（中止原因）；`trace_persist_error` 非空时额外告警提示（对应 Req 8.9 / 8.11 / 8.12）。

> ⚠️ 安全边界：当前后端无鉴权（TD-015）。该页面仅提醒不下单，真实下单能力须等鉴权 + kill-switch UI 之后（超出本特性范围）。

### client.ts — Axios 配置

```typescript
const api = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || 'http://localhost:8000',
  timeout: 30000,
```

### alpha.ts — Alpha 服务

完整封装了 `/api/alpha/*` 下全部端点：
- 状态查询、任务管理
- 数据下载/聚合、CSV 导入
- 数据集/模型/信号 CRUD
- 回测、合约配置
- 统一资源管理

### cnn.ts — CNN 服务

封装 `/api/cnn/*` 端点：
- CNN 状态检查
- 训练启动
- 模型列表/详情/删除

### liveApi.ts — 交易操作台服务

封装 `/api/live/*` 端点（参照 `cnn.ts`）：
- `startDecision` — 触发今日决策（异步，返回 `task_id`）
- `listDecisions` — 决策标识符列表
- `getDecision` — 单条决策详情
- `getDecisionTrace` — 决策过程档案（六段 Decision_Trace）；不吞 404，由 `DecisionTracePanel` 的 `useQuery` 感知并显示「暂无过程档案」

> 类型定义 `types/live.ts`：除 `LiveDecisionRequest` / `Decision` / `RiskDetailItem` / `LiveDecisionResult` 外，新增 `DecisionTrace` 与六段 `TraceSection`（`TraceRunHeaderSection` / `TraceInferenceSection` / `TracePricingSection` / `TraceDecisionLogicSection` / `TraceRiskSection` / `TraceResultSection`），与后端 `decision_trace.py` / `orchestrator.py` 对齐。

## 九、前后端数据流

```
┌─────────────┐     HTTP/WS      ┌─────────────┐
│   React     │ ◄──────────────► │   FastAPI    │
│   Page      │                  │   Backend    │
└──────┬──────┘                  └──────────────┘
       │
  ┌────▼────┐
  │ api/*.ts │  ← Axios 封装
  └────┬────┘
       │
  ┌────▼────────┐
  │ TanStack     │  ← 缓存 + 轮询 + 去重
  │ Query        │
  └────┬────────┘
       │
  ┌────▼────────┐
  │ React State  │  ← useState / Zustand
  └────┬────────┘
       │
  ┌────▼────────┐
  │ Ant Design   │  ← UI 渲染
  │ Components   │
  └─────────────┘
```

**异步任务的完整流程**:
1. 用户在页面提交表单 → `useMutation` 调用 API
2. API 返回 `task_id`
3. 页面开启轮询 `useTaskDetail(taskId, 2000)`
4. 每 2 秒查询任务状态，更新 UI 进度条
5. 任务完成后停止轮询，展示结果

## 交易操作台 · 交易计划自动化

交易操作台页面（`src/pages/TradingConsole/`）以 Tabs 分为两块：

- **手动决策**：既有的 `ConfigForm` + `ProgressCard` + `DecisionResultCard` +
  `RiskDetailPanel` + `HistoryTable`，触发一次今日决策。
- **交易计划**：`PlanManager` 组合视图，管理可复用的「交易计划」。

`PlanManager` 子组件：

| 组件 | 职责 |
|------|------|
| `PlanList` | 计划列表，行内启停（Switch）、立即触发、编辑、删除 |
| `PlanForm` | 新建/编辑表单（弹窗），复用决策配置字段 + 决策时点 / `Data_Basis` / 通知通道多选 / 启用开关 |
| `SchedulerStatusCard` | 调度器运行状态（运行中、轮询周期、启用计划数） |

数据层：`api/liveApi.ts` 新增 `listPlans/getPlan/createPlan/updatePlan/deletePlan/
togglePlan/runPlan/getSchedulerStatus`；类型见 `types/live.ts`（`TradingPlan` /
`TradingPlanRequest` / `TradingPlanSummary` / `SchedulerStatus`）。

「立即触发」复用 `useTask` 轮询任务进度，并联动 `DecisionResultCard` / `RiskDetailPanel`
展示结果。

**安全约束（UI 红线）**：

- 页面始终展示「仅提醒，不自动下单」告警。
- 通知通道仅选择通道名；**前端永不录入/展示任何 webhook/secret/token**，凭证由后端
  环境变量管理。
- `Data_Basis=closed_t` 的计划在后端校验 `decision_time ≥ 15:00`（无前视）。
