## 一、背景与目标

### 1.1 现状

系统目前是**研究 + 回测平台**：数据准备 → CNN 训练/推理出信号 → 共享回测引擎 → Scheme 配置。
能回答「方案历史上是否成立」，但**缺「实盘执行 + 实时监控 + 提醒 + 风控」这一层**。

### 1.2 目标

让「尾盘买入」等方案能**实际、安全、可持续**地运行：
- 每个交易日在决策时点自动产出今日信号并提醒；
- 实时监控持仓/订单/盈亏/信号/系统健康；
- （可选、最后）自动下单，且具备完整风控与高可用保障。

### 1.3 范围

本计划覆盖：实时数据接入、定时调度、信号服务、风控、执行网关、监控看板、提醒推送、每日对账、运维与高可用。
**不**改动既有回测/训练逻辑（仅复用其策略、信号契约、成本与一致性自检）。

## 二、核心原则（可靠 + 高可用，务必遵守）

### 2.1 一致性红线（沿用 docs/07）

- **策略 / 信号 / 成本 / 约束：回测与实盘共用同一套代码**；差异只在执行层（回测撮合 ↔ 券商网关）。
- 实盘信号生成必须复用 `predict_cnn_signals` + `Scheme` + `check_label_strategy_consistency`，不得另写一套。
- 实盘任何临时改参，必须能回到回测复现。

### 2.2 渐进上线（降低不可逆风险）

```
半自动(信号+提醒+人工下单) → 纸面/模拟盘对账 → 实盘小资金灰度 → 全自动(强风控)
```

每升一级都要先满足上一级的「上线门禁」（见第八节）。

### 2.3 可靠性原则（correctness）

| 原则 | 说明 |
|---|---|
| 幂等下单 | 每个目标仓位/订单带唯一 `client_order_id`，重复提交不产生双重下单 |
| 状态持久化 | 信号、订单、成交、持仓、任务状态落盘（DB），进程重启可恢复 |
| 订单状态机 | 明确 提交中/已报/部成/全成/已撤/拒单 状态流转，超时有兜底 |
| 重试与超时 | 网络/接口调用带超时 + 有限重试 + 退避；不可重试错误明确区分 |
| 交易日历/时钟 | 用交易日历判断是否开盘；统一时区与时间戳精度；NTP 校时 |
| 对账 | 每日理论持仓/PnL vs 实盘，差异超阈值告警并阻断下一轮自动下单 |
| 审计可追溯 | 信号→决策→下单→成交 全链路留痕，绑定模型/Scheme 版本 |

### 2.4 高可用原则（availability）

| 原则 | 说明 |
|---|---|
| 无单点 | 关键路径（数据/调度/执行）避免单点；数据源已有 Tushare→Mock 降级链可借鉴 |
| 自动恢复 | 进程守护（systemd/supervisor/pm2）崩溃自动重启；重启后从持久化状态恢复 |
| 单实例互斥 | 执行/下单进程用分布式锁/文件锁，**严禁多实例并发下单** |
| 健康检查/心跳 | 各服务暴露 health + 定期心跳；心跳丢失触发告警与（可选）故障转移 |
| 优雅降级 | 数据源故障→降级数据/暂停下单而非乱下单；提醒通道多路冗余 |
| 可观测性 | 指标(metrics) + 结构化日志 + 关键事件告警，闭环到人 |
| 故障转移 | 实盘阶段主备热备，主节点失联备节点接管（带防脑裂） |

### 2.5 安全

- 券商凭据/Token 用环境变量或密钥管理，不入库、不入仓库（`.env` 已在 .gitignore）。
- 风控前置：任何下单前过风控；保留人工 **kill-switch**（一键停止所有自动交易）。
- 最小权限：自动交易账户独立、限额。

| 模块 | 作用 | 必要性 | 现状 |
|---|---|:---:|---|
| 实时/准实时行情接入 | 决策时点的当日分钟线 | 🔴 必须 | 仅历史下载；WS 有 tick 主题无数据 |

## 四、分阶段迭代计划

> 排序原则：**先把"产信号 + 提醒 + 监控 + 风控"这条不下单的安全闭环做扎实，再逐级放开执行权限**。

### 迭代 6 · 半自动信号服务（不下单，最先落地）

- **目标**：每交易日决策时点自动产出今日信号并提醒，人工下单。
- **模块/改动（预估）**：
  - 实时数据接入：决策时点拉取当日分钟线（数据源增量/准实时）。
  - 调度器：交易日历驱动的定时任务（如每日 14:45），可配置时点；幂等（同日不重复触发）。
  - 信号服务：复用 `predict_cnn_signals` + `Scheme`（`exit_mode=auto`）产出「买/不买 + 标的 + 建议手数 + 价位」。
  - 前置风控（最小版）：标的黑名单、单票/总仓位上限、停牌/涨跌停过滤。
  - 提醒推送：抽象 `Notifier`（钉钉/企微/server酱/邮件其一起步），失败重试 + 多通道兜底。
  - 持久化：每日信号与决策落盘（DB/JSON），可回溯。
- **验收标准**：
  - 模拟"今天"运行 → 在配置时点产出决策并成功推送（含失败重试）；
  - 同日重复触发不产生重复提醒（幂等）；
  - 非交易日/停牌标的被正确跳过；
  - 决策可在持久化中查到，且与回测口径一致（复用同一信号/一致性自检）。
- **可靠性/HA 要点**：调度幂等、交易日历判断、提醒多通道、决策落盘可恢复。
- **风险等级**：🟡 中。
- **状态**：✅ 完成（2026-06-06）

**实现说明（v0.2）**：`live/` 包落地——`calendar.TradingCalendar`(交易日历)、`scheduler.should_trigger`(幂等触发)、`notifier`(Log/Multi/Retry，单通道失败隔离)、`risk.RiskManager`(黑名单/单票·总仓上限/停牌/单日熔断/kill-switch)、`decision`(Decision + DecisionStore 幂等持久化)、`signal_service.SignalService`(信号→风控→提醒→落盘，幂等，复用回测阈值口径)。测试 `backend/tests/test_live_iteration6.py`（12 项）。**不下单，可立即用于尾盘提醒。**

### 迭代 7 · 监控与对账

- **目标**：实时看板 + 每日对账 + 系统健康可观测。
- **模块/改动（预估）**：
  - WS 实时推送：把已定义主题（tick/order/trade/position/account/log/task）接上真实数据。
  - 前端监控看板：持仓/盈亏/今日信号/订单流水/系统日志/健康状态。
  - 每日对账：理论持仓/PnL（由信号+成交推算）vs 实际（人工录入或网关查询）；差异超阈值告警。
  - 健康检查/心跳：各服务 health 端点 + 心跳；异常告警。
- **验收标准**：
  - 看板能实时反映持仓/盈亏/信号变化；
  - 对账差异超阈值时产生告警；
  - 任一服务心跳丢失 → 告警可达。
- **可靠性/HA 要点**：心跳与健康检查、告警闭环、对账阻断（差异过大时禁止下一轮自动下单）。
- **风险等级**：🟡 中。
- **状态**：✅ 完成（2026-06-06）

**实现说明（v0.3）**：`monitoring.MonitorHub`(持仓/账户/成交/盈亏快照，供 WS 推送) + `HeartbeatMonitor`(心跳超时判定不健康)；`reconciliation.reconcile`(持仓 + 市值/盈亏对账，差异超阈值 `should_block` 阻断自动下单)。测试 `backend/tests/test_live_iteration7.py`（6 项）。

### 迭代 8 · 执行网关与模拟盘（复用 BaseStrategy）

- **目标**：抽象券商网关，先跑纸面/模拟盘，验证"信号→下单→成交→持仓"闭环与一致性。
- **模块/改动（预估）**：
  - `BrokerGateway` 协议：`send_order/cancel_order/query_orders/query_positions/query_account`。
  - 模拟网关 `PaperBroker`：用实时行情撮合，复用回测的成交/成本口径。
  - 实盘交易引擎 `LiveTrader`：复用 `BaseStrategy` + 信号契约，把"回测撮合"替换为网关下单（策略类不变）。
  - 订单状态机 + 幂等 `client_order_id` + 超时兜底（未成回报、部成处理）。
- **验收标准**：
  - 同一 Scheme/策略，纸面盘与回测在相同输入下持仓/成交方向一致（口径对齐）；
  - 重复提交同一决策不产生双重下单（幂等）；
  - 断线重连后订单/持仓状态可恢复一致。
- **可靠性/HA 要点**：幂等下单、订单状态机、状态持久化恢复、单实例互斥锁。
- **风险等级**：🟠 中高（执行层是新乐观假设/bug 的高发区）。
- **状态**：✅ 完成（2026-06-06）

**实现说明（v0.4）**：`gateway.BrokerGateway` 协议(send/cancel/query) + `OrderRequest/OrderReport`(`client_order_id` 幂等键)；`paper_broker.PaperBroker`(模拟盘，佣金/印花税口径同回测，重复 client_order_id 去重，资金/持仓不足拒单)；`live_trader.LiveTrader`(目标仓位→订单，幂等，持仓以网关为权威源、可重启恢复)。测试 `backend/tests/test_live_iteration8.py`（8 项）。

### 迭代 9 · 实盘小资金 + 全风控

- **目标**：接真实券商网关，小资金灰度，配齐风控与人工干预。
- **模块/改动（预估）**：
  - 接入 A 股个人可用网关（如 QMT/miniqmt、Ptrade；按券商支持选择）。
  - 完整风控：单笔/单票/总仓位限额、单日最大亏损熔断、异常行情暂停、撤单超时、重复/异常订单拦截。
  - 人工 kill-switch（一键停止自动交易并撤单）。
  - 审计：全链路留痕，绑定模型/Scheme/参数版本。
- **验收标准**：
  - 触发各风控条件时按预期拦截/熔断/告警；
  - kill-switch 能即时停止并撤未成交单；
  - 每日对账通过；小资金运行 N 个交易日无未受控异常。
- **可靠性/HA 要点**：风控前置且不可绕过、熔断与对账联动、审计完整、凭据安全。
- **风险等级**：🔴 高（真实资金）。
- **状态**：✅ 完成（2026-06-06，框架级；真实券商对接为集成点）

**实现说明（v0.5）**：`audit.AuditLog`(append-only JSONL，signal→decision→order 全链路可追溯，绑定版本)；`guarded_gateway.RiskGuardedGateway`(包裹任意网关，下单前过 kill-switch / 单日熔断 / 对账阻断 并审计，**绕不过去**)；`live_broker.StubLiveBroker`(真实券商适配桩，未注入 connector 即拒绝下单，集成点明确)。测试 `backend/tests/test_live_iteration9.py`（7 项）。**残余风险：真实券商 connector（QMT/miniqmt、Ptrade）需外部 SDK + 凭据对接；小资金灰度需真实环境，无法在此自动验证。**

### 迭代 10 · 高可用与运维

- **目标**：生产级稳定性与可恢复性。
- **模块/改动（预估）**：
  - 进程守护与自动重启（systemd/supervisor）；重启后从持久化恢复。
  - 主备/故障转移（带防脑裂的单实例下单保证）。
  - 任务/状态持久化升级（当前任务状态仅内存 → DB，见 docs/06 TD）。
  - 可观测性：metrics（Prometheus 等）+ 结构化日志 + 关键事件告警 + 演练手册。
  - 灾备恢复演练：杀进程/断网/数据源故障 下的行为符合预期（暂停而非乱单）。
- **验收标准**：
  - 杀掉任一关键进程 → 自动重启并状态一致；
  - 数据源故障 → 自动降级/暂停下单并告警；
  - 演练：断网恢复后无重复下单、无持仓漂移。
- **可靠性/HA 要点**：无单点、自动恢复、降级优先、可观测、定期演练。
- **风险等级**：🔴 高。
- **状态**：✅ 完成（2026-06-06，代码级原语；部署/运维为外部配置）

**实现说明（v0.6）**：`single_instance.SingleInstanceLock`(flock 单实例互斥，防并发下单，支持主备接管)；`degradation.decide_trading`(行情过期/系统不健康/对账阻断 → 降级暂停，**降级优先于猜测**)；`runtime_state.RuntimeStateStore`(轻状态持久化，重启不重复触发/下单)。测试 `backend/tests/test_live_iteration10.py`（6 项）。**残余风险：systemd/supervisor 守护、主备热备、Prometheus metrics、灾备演练 属部署/运维配置，需在目标环境落地。**

### 迭代 11 · 交易操作台（暴露 live 原语的 UI + API 层，不下单）

- **目标**：把迭代 6 已落地的实盘原语经一组 HTTP 接口 + 交互式前端页面暴露出来，让用户在临近收盘时基于 CNN 预测产出「今日是否买入」的决策与风控明细，**仍不下单**。
- **本质**：这是**暴露层**，不是新建预测引擎。决策完全复用既有 `predict_cnn_signals`（CNN 推理）→ `SignalService`（信号→风控→提醒→落盘编排，幂等）→ `RiskManager`（风控）→ `Notifier`（提醒）→ `DecisionStore`（幂等持久化）。
- **一致性红线**（沿用 2.1）：实盘与回测**共用同一套信号/成本/风控代码**，本特性只是把既有 `live/` 原语经 API 暴露，不重写任何决策/风控/推理逻辑。
- **新增（仅薄粘合）**：
  - `RiskInspector`（风控明细薄包装）：包住 `RiskManager`，逐项记录 `{check, passed, detail}`，**判定权威仍是 `RiskManager`**（明细仅展示/审计，避免双实现漂移）。
  - `config.LIVE_DECISION_PATH = AITRADE_HOME/live/decisions`（决策存储目录接线）。
  - `LiveSignalOrchestrator`（编排器，串联既有原语）、`/api/live/*` 路由、Pydantic 请求模型、`TaskType.LIVE_DECISION`。
  - 前端 `TradingConsole` 页面 + `liveApi.ts` + `types/live.ts`（详见 docs/04）。
- **接口**（详见 docs/03）：`POST /api/live/decision`（异步，返回 `task_id`，进度经 `/ws` 推送）、`GET /api/live/decisions`、`GET /api/live/decisions/{signal_id}`。
- **安全边界（v1 明确约束）**：
  - **无真实下单**：Decision_API 不 import 也不调用任何券商网关/下单接口；产出仅限 Decision 落盘 + Notifier 提醒（属性测试 Property 7 守护）。
  - **无鉴权环境**：当前后端 `CORS=["*"]`、无认证（技术债 **TD-015**）。本特性不下单，风险可控；接口文档已标注「当前无鉴权，真实下单能力依赖**鉴权 + kill-switch UI** 前置条件」（Req 7.3）。
  - 前端结果区始终显示「仅提醒，不自动下单」（Req 7.4）。
- **验收标准**：
  - 触发今日决策返回 `task_id`，进度经 WS 刷新，完成后展示 `decision` + `risk_detail`；
  - 同 `signal_id` 二次触发幂等（不重复写、不重复提醒）；
  - 风控拦截 → `action=hold` 且 reason 含原因；风控明细完整覆盖 5 项且结论与 `RiskManager` 一致；
  - 模型不存在 → 404、缺必填 → 400、决策日行情缺失 → 任务 `FAILED` 且 message 含「行情缺失」。
- **风险等级**：🟢 低（不下单、纯暴露层）。
- **状态**：✅ 完成（spec `trading-console`）

#### 决策过程可观测性（v0.8，对应 spec Requirement 8）

把「每次决策从输入到落盘的完整推理与风控过程」做成可观测、可重启回溯的档案，用于理解决策依据、排查异常与事后审计。沿用「复用优先、最小侵入」：仅新增一个可选 `on_meta` 回调（向后兼容）、`decision_trace.py`、一个 trace 路由、前端面板与 orchestrator 薄接线，**不重写任何决策/风控/推理逻辑**，且 `DecisionStore` 决策 schema 零改动。

- **两层可观测性**（共享同一套**六段 Trace_Section** 语义：运行头/推理段/取价段/决策逻辑段/风控段/结果段）：
  - **标准 `logging`（实时排障）**：`logging.getLogger("aitrade.live.orchestrator")`。六段**里程碑打 INFO**、重负载**明细打 DEBUG**（逐证券 bar 数、信号逐点、风控逐项 detail）；**每行带 `run_id` 前缀**（`run_id = uuid4().hex[:8]`），便于在并发运行的日志里按 `run_id` 串起一次完整运行。默认 INFO 级即得到干净的六段时间线，开 DEBUG 才放出明细。
  - **可持久化 `Decision_Trace`（可重启回溯）**：每个 `signal_id` 写一份 sibling 文件 `{signal_id}.trace.json`（与既有 `{signal_id}.json` 并列、独立），系统重启后仍可经 `GET /api/live/decisions/{signal_id}/trace` 回溯（Req 8.2 / 8.4）。
- **脱敏红线**（Req 8.7 / 8.8，属性测试 Property 13 守护）：
  - `logging` 与 `Decision_Trace` 均**不含任何凭证**（含 **Tushare token**）；
  - 数据源仅以**类型（`upload`/`pull`）+ bar 数量**记录，绝不记录 token 或连接细节；
  - 运行头（`run_header`）的风控配置仅存**摘要**（`max_total_position_ratio` / `max_single_position_ratio` / `allow_when_halted` + `blacklist_size` 黑名单长度），不展开黑名单内容。
- **best-effort 持久化**（Req 8.12）：`Decision_Trace` 在 **Decision 已落盘后**才写入（`DecisionTraceStore.save_if_absent`）；写失败仅 `logger.warning` 并在结果段标注 `trace_persisted=false` + `trace_persist_error`，**绝不影响 Decision 自身落盘与返回**。
- **幂等与中止语义**：
  - 幂等命中（同 `signal_id` 二次触发）**不写入新 trace**，返回首次已持久化档案，结果段标注 `idempotent_hit=true`（Req 8.9 / 8.10）；
  - 产出 Decision 前因错误中止（行情/信号缺失等），`completed_sections` 仅为失败点之前的前缀，结果段记 `abort_reason` 且不含成功决策字段（Req 8.11）。
- **接口/前端**（详见 docs/03、docs/04）：`GET /api/live/decisions/{signal_id}/trace`（不存在 → 404「决策过程档案不存在」）；前端 `DecisionTracePanel` 六段可折叠分组，懒加载（展开才请求 `/trace`），404 显示「暂无过程档案」，结果段展示 `idempotent_hit`/`trace_persisted`/`abort_reason`。
- **测试**：新增 Property 9–15 各一条 Hypothesis 属性测试（六段完整性/持久化往返/与 Decision 关联且不改 schema/幂等不新增 trace/日志与 trace 无敏感字段/中止只记前缀/持久化失败不影响 Decision，各 `max_examples=100`）+ 单元/路由测试；前端 `DecisionTracePanel` 示例/快照测试。
- **状态**：✅ 完成（spec `trading-console` 可观测性增量，任务 13–21）。

## 六、关键红线与残余风险

### 6.1 红线（不可破）

- 实盘与回测**共用策略/信号/成本/约束代码**，差异只在执行层。
- **严禁多实例并发下单**（单实例互斥）。
- 下单**必过风控**，且保留 kill-switch。
- 自动交易前必须经过纸面/模拟盘对账与小资金灰度。
- 凭据不入库、不入仓库。

### 6.2 残余风险（持续关注）

- 实时数据延迟/缺失导致决策时点信息不全（需超时与降级策略）。
- 券商接口限频/拒单/维护窗口（需重试、退避、告警）。
- 尾盘流动性不足导致建议手数无法成交（需流动性约束 + 纸面复核）。
- 模型/市场 regime 漂移导致 alpha 衰减（需监控与定期再评估）。

## 七、可靠性 & 高可用 设计要点（专项）

1. **幂等键贯穿全链路**：`signal_id`（日期+Scheme+模型版本）→ `decision_id` → `client_order_id`，任一环重放不产生副作用。
2. **状态机 + 持久化**：订单/持仓/任务状态写 DB；进程重启从 DB 恢复，启动先做"在途订单核对"。
3. **超时与对账兜底**：下单后未在阈值内收到回报 → 主动查询；每日收盘后强制对账，差异阻断次日自动下单。
4. **降级优先于猜测**：数据/接口异常时**暂停下单并告警**，绝不在信息不全时下单。
5. **单实例下单锁**：分布式锁或文件锁 + 租约；主备切换防脑裂（fencing token）。
6. **观测闭环**：指标（信号产出延迟、下单成功率、对账差异、心跳）→ 阈值告警 → 人；告警必须可达（多通道）。
7. **演练即验收**：杀进程、断网、数据源故障、券商拒单 四类故障注入演练纳入迭代 10 验收。

## 八、上线门禁（Go-Live Checklist，逐级放开执行权限）

```
□ 半自动稳定运行 ≥ N 个交易日，提醒准确、无漏触发/重复触发
□ 纸面/模拟盘对账：理论 vs 实际 成交方向/价/量 差异在阈值内
□ 成本敏感性（佣金×2、滑点+5bp）下方案仍成立（复用 validation 工具）
□ 样本外/walk-forward 验证通过，最近 1~2 年留出集不参与调参
□ 风控全部生效（限额/熔断/暂停/kill-switch 已演练）
□ 幂等下单、断线恢复、单实例互斥 已演练通过
□ 监控看板 + 告警闭环可用，心跳/健康检查就绪
□ 凭据安全、审计可追溯、模型/Scheme 版本绑定
□ CNN 生产模型由治理模块晋级产生，且通过治理回放证明优于固定模型/无脑重训基准
□ 故障注入演练（杀进程/断网/数据源故障/拒单）行为符合预期
□ 小资金灰度通过后，再逐步放大额度
```
