## 二、已知技术债务

### 🔴 关键问题

#### TD-001: `alpha/lab.py` 过大 (~59K)
- **位置**: `backend/aitrade/alpha/lab.py`
- **问题**: AlphaLab 单文件包含全部数据 I/O、数据集管理、CSV 导入等功能
- **影响**: 修改任何一个功能都需要在巨大文件中定位，代码审查困难
- **建议**: 拆分为 `lab_io.py`, `lab_datasets.py`, `lab_csv.py` 等

#### TD-002: `api/alpha.py` 过大 (~1340 行)
- **位置**: `backend/aitrade/api/alpha.py`
- **问题**: 单个路由文件包含全部 Alpha API + 业务逻辑
- **影响**: 路由层与业务逻辑耦合，新增 API 时文件膨胀
- **建议**: 将业务逻辑提取为 service 层，路由文件只做参数校验和调用转发

#### TD-003: `cnn/model.py` 职责过载
- **位置**: `backend/aitrade/cnn/model.py`
- **问题**: 特征工程 + 数据加载 + 标签生成 + 网络定义全部混在 487 行文件中
- **建议**: 拆分为 `features.py`, `dataset.py`, `network.py`

#### TD-004: CNN 网络类定义在闭包内
- **位置**: `cnn/model.py` L412-L475
- **问题**: `GroupAwareMarketCNN` 定义在 `create_market_cnn()` 函数内部，pickle 路径不稳定
- **影响**: 函数签名变化时旧 checkpoint 无法加载
- **建议**: 将类提升为模块级定义

### 🟡 重要改进

#### TD-005: CNN 特征计算使用 Python 循环
- **位置**: `cnn/model.py` L181-L190
- **问题**: `volume_ratio`, `ma5_diff`, `ma20_diff` 逐行循环计算
- **影响**: 分钟级数据性能瓶颈
- **建议**: 改为 NumPy 向量化运算

#### TD-006: `iter_rows` 逐行提取数据
- **位置**: `cnn/model.py` L153-L167
- **问题**: 将 Polars DataFrame 逐行转为 dict 列表，丢失列式处理优势
- **建议**: 直接用 `to_numpy()` 获取列向量

#### TD-007: `list_cnn_models` 加载全量权重
- **位置**: `cnn/storage.py` L51-L57
- **问题**: 列表接口 `torch.load` 每个模型的完整权重只为读元数据
- **建议**: 保存时额外输出 `{name}_meta.json`

#### TD-008: CNN 二分类标签信息损失
- **位置**: `cnn/model.py` L369-L370
- **问题**: 涨跌幅硬编码为二分类 (>0 → 1.0)，无阈值/无回归模式
- **建议**: 增加 `label_type` 参数 (binary/ternary/regression)

#### TD-009: CNN 使用 BCELoss 而非 BCEWithLogitsLoss
- **位置**: `cnn/trainer.py` L148
- **问题**: 数值不稳定，且对类别不平衡无感知
- **建议**: 去掉网络末层 Sigmoid，改用 BCEWithLogitsLoss + pos_weight

#### TD-010: CNN 训练/验证仅简单截断
- **位置**: `cnn/trainer.py` L108-L115
- **问题**: 无独立测试集，无时序交叉验证
- **建议**: 增加 expanding window CV 选项

## 三、功能迭代路线图

### Phase 1 — 核心补全 (v0.2.0)

> 目标：补全 CNN 推理能力，修复关键技术债务

| 功能 | 优先级 | 描述 |
|------|--------|------|
| CNN 推理接口 | P0 | 添加 `predict` 函数和 `/api/cnn/predict` API |
| CNN model.py 拆分 | P0 | 拆为 features / dataset / network 三个文件 |
| CNN 网络类提升 | P1 | 将 GroupAwareMarketCNN 移为模块级类 |
| CNN 特征向量化 | P1 | 消除 Python 循环，改为全 NumPy |
| CNN 模型列表轻量化 | P1 | 引入 meta.json 避免加载全量权重 |
| alpha.py 路由拆分 | P1 | 业务逻辑提取为独立 service 层 |

### Phase 2 — 模型能力增强 (v0.3.0)

> 目标：增强预测能力，提升模型可靠性

| 功能 | 优先级 | 描述 |
|------|--------|------|
| CNN 回归/三分类标签 | P2 | label_type 参数支持 binary/ternary/regression |
| CNN BCEWithLogitsLoss | P2 | 改进损失函数 + 类别不平衡处理 |
| CNN 数据增强 | P2 | 高斯噪声 / 时间窗口裁剪 / Mixup |
| CNN 时序交叉验证 | P2 | Expanding/Sliding window CV |
| Alpha 自定义因子 | P2 | 支持用户自定义因子表达式 |
| Alpha 因子 IC/IR 分析 | P2 | 因子评价指标可视化 |

### Phase 3 — 生产就绪 (v0.4.0)

> 目标：安全、可靠、可监控

| 功能 | 优先级 | 描述 |
|------|--------|------|
| 任务持久化 (SQLite) | P1 | 任务状态写入 tasks.db，重启不丢失 |
| 模型版本管理 | P2 | 支持版本号、覆盖确认、版本对比 |
| CNN 模型治理 | P1 | WF/OOS 评估、候选模型、人工晋级、回滚、治理回放回测（详见 `10-CNN模型滚动评估与半自动晋级.md`） |
| 用户认证 | P2 | JWT / Session 认证 + RBAC |
| CORS 安全配置 | P3 | 生产环境限制允许来源 |
| 日志聚合 | P3 | 结构化日志 + 文件轮转 |
| 前端 ErrorBoundary | P3 | 全局错误兜底 |

### Phase 4 — 实时交易 (v1.0.0)

> 目标：从研究走向实盘

| 功能 | 优先级 | 描述 |
|------|--------|------|
| 实时行情接入 | P1 | 通过 WebSocket 推送实时 Tick |
| 在线推理 | P1 | CNN / Alpha 模型的在线预测服务 |
| 下单接口 | P2 | 对接券商 API |
| 风控模块 | P2 | 持仓限制、止损止盈 |
| 策略调度器 | P2 | 定时执行策略逻辑 |
| 绩效监控 | P3 | 实盘 PnL 追踪和报告 |
